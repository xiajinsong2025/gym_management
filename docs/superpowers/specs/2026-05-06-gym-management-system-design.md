# 健身房管理系统设计

日期：2026-05-06

## 1. 背景与目标

本系统面向单一健身房/健身工作室的后台管理场景，参考 `evangui/multi-fitness-console` 的业务模块，但收敛当前范围：

- 不开发移动端页面。
- 不开发多俱乐部、多商户、总后台。
- 采用 FastAPI、Vue3、SQLAlchemy、Alembic 技术栈。
- 移动端相关能力以 API 和数据模型预留，第一期由后台管理端代操作。

第一期目标是交付一个可运营的 Web 后台，覆盖会员、卡项、签到、课程、私教、订单、财务报表和系统权限等核心流程。

## 2. 总体方案

采用“单俱乐部后台 + 移动端 API 预留”的设计。

业务上先完整建模会员、卡项、课程预约、私教消课、训练记录、反馈、财务和权限。前端只实现 Vue3 后台管理页面，移动端相关入口保留在后端 API 命名空间和数据模型中，后续可接小程序、App 或 H5。

系统不引入租户隔离字段，不设计多俱乐部切换、商户后台、平台总后台。但保留 `club_settings` 作为单俱乐部基础配置，避免俱乐部信息散落在多个表中。

## 3. 技术架构

### 3.1 后端

后端使用 FastAPI：

- `app/main.py`：应用入口，注册中间件、异常处理、路由。
- `app/core`：配置、数据库连接、JWT、RBAC、日志、异常。
- `app/api/v1`：HTTP 路由，按业务模块拆分。
- `app/schemas`：Pydantic 请求和响应模型。
- `app/models`：SQLAlchemy ORM 模型。
- `app/services`：业务服务，承载开卡、签到、预约、消课等事务逻辑。
- `app/repositories`：复杂查询、分页查询和报表查询。
- `app/utils`：通用工具。
- `alembic`：数据库迁移。
- `tests`：单元测试和接口测试。

推荐数据库为 PostgreSQL。开发期可以使用 SQLite，但迁移和生产部署应以 PostgreSQL 为准。

### 3.2 前端

前端使用 Vue3：

- Vue3 + Vite + TypeScript。
- Vue Router 管理路由。
- Pinia 管理登录用户、权限、菜单、字典缓存。
- Axios 封装 API 请求、认证头、错误处理。
- Element Plus 作为后台组件库。
- ECharts 用于经营看板和财务报表。

后台布局采用左侧菜单、顶部用户区、主内容区的传统管理系统结构。菜单由后端权限接口返回，前端根据权限动态生成。

## 4. 功能模块

### 4.1 控制台

提供经营概览和快捷入口：

- 今日签到人数。
- 今日课程和预约人数。
- 新增会员、潜在客户、即将到期会员。
- 今日收入、本月收入。
- 待跟进客户、待确认私教课。
- 快捷入口：添加会员、会员充值、前台签到、课程排课。

### 4.2 系统管理

后台基础权限和审计：

- 用户管理。
- 角色管理。
- 菜单管理。
- 权限管理。
- 部门管理。
- 字典管理。
- 通知公告。
- 登录日志。
- 操作日志。

权限模型采用 RBAC：用户绑定角色，角色绑定菜单和权限标识。接口使用权限依赖校验。

### 4.3 基础设置

单俱乐部基础运营资料：

- 俱乐部信息设置。
- 营业时间设置。
- 场地/教室管理。
- 员工管理。
- 教练管理。
- 课程类型。
- 卡种配置。
- 支付方式配置。

### 4.4 会员管理

覆盖会员全生命周期：

- 会员列表。
- 添加会员。
- 会员导入。
- 会员详情。
- 会员维护跟进。
- 潜在客户。
- 训练情况记录。
- 会员反馈管理。
- 会员状态管理：正常、冻结、过期、流失、潜客。

会员手机号需要唯一。会员卡号可自动生成，也允许后台手动录入。

### 4.5 卡项与订单

支持常见健身房卡项：

- 时间卡。
- 次卡。
- 储值卡。
- 私教卡。

核心操作：

- 开卡。
- 续卡。
- 充值。
- 冻结/解冻。
- 转卡。
- 退卡。
- 到期提醒。
- 卡项流水。

所有涉及金额、次数、有效期变化的操作必须产生订单或卡项流水，避免直接修改余额、次数和有效期。

### 4.6 前台业务

面向前台工作人员：

- 前台签到。
- 签退。
- 会员查询。
- 手环借出。
- 手环归还。
- 课程播报数据。
- 大屏数据接口。

第一期不对接真实硬件。手环借还以后台记录为准，后续可接设备接口。

### 4.7 课程管理

面向团课和公开课：

- 课程分类。
- 课程管理。
- 课程排期。
- 教室占用。
- 后台代预约。
- 预约记录。
- 候补。
- 取消预约。
- 课程签到。
- 容量控制。

移动端预约 API 预留在 `/api/v1/mobile/course-bookings`，第一期不开发移动端页面。

### 4.8 私教管理

面向一对一私教业务：

- 私教课包。
- 私教排课。
- 私教预约。
- 私教确认。
- 私教消课。
- 训练情况跟踪。
- 教练课时报表。

私教消课必须校验会员课包余量、课程状态、教练归属和确认状态。

### 4.9 营销活动

第一期做轻量营销：

- 营销活动添加。
- 营销活动管理。
- 活动报名记录。
- 潜客转化统计。

优惠券、复杂赠课、积分、健身圈、新闻推送暂缓。

### 4.10 财务报表

第一期报表：

- 充值收入。
- 办卡收入。
- 私教收入。
- 退款记录。
- 消课统计。
- 会员余额。
- 教练课时统计。
- 日/月收入汇总。

报表查询由后端 repository 层提供聚合查询，前端只负责筛选和展示。

### 5.2 俱乐部与员工

- `orders`：订单。

### 5.5 签到与前台

- `bracelet_records`：手环借还记录。

### 5.6 课程与预约

- `course_categories`：课程分类。
- `courses`：课程。
- `course_schedules`：课程排期。

### 5.7 私教

### 5.8 营销与通知

- `notifications`：通知公告。

## 6. API 设计

统一前缀：`/api/v1`。

主要路由：

- `/auth`：登录、刷新 token、退出、当前用户。
- `/system/users`：用户管理。
- `/system/roles`：角色管理。
- `/system/menus`：菜单管理。
- `/system/dictionaries`：字典管理。
- `/club/settings`：俱乐部配置。
- `/staff`：工作人员。
- `/coaches`：教练。
- `/members`：会员。
- `/member-cards`：会员卡。
- `/checkins`：签到。
- `/courses`：课程。
- `/course-schedules`：课程排期。
- `/course-bookings`：课程预约。
- `/personal-training/packages`：私教课包。
- `/personal-training/sessions`：私教排课和消课。
- `/orders`：订单。
- `/payments`：支付。
- `/refunds`：退款。
- `/reports`：财务和经营报表。
- `/marketing/campaigns`：营销活动。
- `/mobile`：移动端预留 API。

接口返回结构统一：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

分页结构统一：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 20
}
```

## 7. 关键业务流程

### 7.1 会员开卡

1. 创建或选择会员。
2. 选择卡种。
3. 创建订单。
4. 记录支付。
5. 支付成功后生成 `member_cards`。
6. 写入 `card_transactions`。

余额、次数和有效期只能通过服务层事务变更。

### 7.2 前台签到

1. 通过手机号、会员卡号或姓名查询会员。
2. 校验会员状态。
3. 校验可用卡项。
4. 创建签到记录。
5. 可选登记手环借出。
6. 签退时更新记录并归还手环。

### 7.3 团课预约

1. 后台创建课程和排期。
2. 后台代预约或移动端 API 预约。
3. 校验课程容量、会员状态、卡项资格。
4. 创建预约记录。
5. 上课签到。
6. 根据课程规则扣次或记录课时。

### 7.4 私教消课

1. 会员购买私教课包。
2. 后台安排私教课程。
3. 课程开始前可调整排期。
4. 上课后由后台或教练确认。
5. 扣减课包剩余次数。
6. 生成训练记录和教练课时数据。

## 9. 权限设计

权限粒度分为：

- 菜单权限：控制页面是否可见。
- 操作权限：控制新增、编辑、删除、导入、导出、审核、退款、消课等按钮。
- 数据权限：第一期只支持全部数据，不做部门级或教练级数据隔离。后续可增加“仅本人”或“所属部门”范围。

接口权限由 FastAPI dependency 校验，前端权限仅用于显示控制，不能作为安全边界。

## 10. 非功能要求

- 所有写操作记录操作日志。
- 登录失败和成功记录登录日志。
- 金额使用整数分或 Decimal，禁止使用 float。
- 涉及订单、支付、开卡、扣次、消课的操作必须使用数据库事务。
- 关键列表支持分页、搜索、排序。
- 导入会员需要返回成功数、失败数和失败原因。
- 后端接口需要统一异常结构。
- Alembic 管理全部表结构迁移。

- 课程预约容量校验。
- 私教消课扣次。

前端测试重点：

- 会员列表筛选。
- 开卡表单。

- 课程排课。
- 私教消课。
